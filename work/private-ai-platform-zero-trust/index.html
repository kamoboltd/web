Work

A private AI platform for documents that cannot leave the building

Self-hosted inference and RAG for a global professional education body.

Zerodocuments sent to an outside AI service
Separatestore per use case, so one team's documents can never surface in another team's answers

The problem

Real demand for retrieval over internal documents, and an absolute constraint that those documents could not be sent to a third-party model API. Several separate use cases, each with its own sensitivity, which could not be allowed to see each other's data.

What we did

Built GPU-accelerated Azure infrastructure defined in Terraform and Ansible, running self-hosted inference on vLLM, Ollama and llama.cpp. Added a document ingestion pipeline, vector storage on Postgres with pgvector plus Chroma and LanceDB, Redis for caching and RabbitMQ for message handling, behind a clustered NGINX reverse proxy. Built the API layer and a React chat front end with single sign-on and a configuration page. Every use case runs on its own isolated platform with its own dedicated private vector store, so data never crosses between them. Zero trust and least privilege throughout, containerised, automated with GitHub Actions, observable through Grafana.

Where it landed

In production, serving several use cases, with scale handled by adding nodes rather than rebuilding.

What to take from this

  • "We cannot use the API models" is a platform problem, not a reason to abandon the use case.
  • Isolation per use case costs more than one shared index and is usually the only answer that survives a security review.
  • Self-hosted inference is an infrastructure project wearing an AI hat. Most of the work is GPU capacity, networking and identity.
  • Put the configuration in a page someone else can operate, or you become the dependency.

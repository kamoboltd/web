FAQ

Common questions about Azure landing zone consultancy

What is an Azure landing zone?

An Azure landing zone is the governed foundation you deploy before any workloads: management groups, subscriptions, networking, identity, policy and monitoring, arranged so new applications land in a secure, consistent environment. Microsoft's Cloud Adoption Framework defines the reference design; we implement it in Terraform and right-size it to your organisation.

Should we use Terraform or Bicep for Azure landing zones?

Microsoft's accelerators support both. Bicep suits Azure-only teams already invested in ARM templates. We recommend Terraform when you want one language across clouds and SaaS providers, a mature module ecosystem, and explicit state that makes drift visible. We build in Terraform on Azure Verified Modules because it also covers the rest of your stack, from DNS to GitHub.

How long does it take to build an Azure landing zone?

A right-sized build for a small estate takes days of engineering plus a few design workshops. A full platform build with pipelines, a policy baseline and subscription vending typically runs several weeks. The biggest variables are network topology and identity decisions, which is why we start with a short scoping call before quoting a timeline.

How much does an Azure landing zone cost?

There are two costs: the build and the Azure run-rate. Our engagements are day-rate anchored senior engineering from £550 per day, with fixed prices quoted after a scoping call. The platform run-rate covers things like firewalls, logging and Defender for Cloud, and we size it deliberately so a small estate is not paying enterprise prices.

Do smaller organisations need a full enterprise landing zone?

No. The enterprise reference architecture exists for large estates. A smaller organisation usually needs a subset: production separated from non-production, role-based access, a policy baseline, budgets and centralised logging. We right-size the design so you get the governance without the overhead, and because it is all code, growing into more later is straightforward.

What is subscription vending?

Subscription vending automates how new Azure subscriptions are requested, created and governed. Instead of hand-building each one, a pipeline stamps out subscriptions with networking, policy, budgets and access already applied. It is how platform teams hand application teams a compliant landing zone in hours rather than weeks, and we implement it in Terraform.

Can you bring an existing Azure environment under a landing zone?

Yes, brownfield work is common. We map what exists, import resources into Terraform state, then introduce management groups, policy and networking incrementally so nothing breaks in flight. Most estates can adopt landing zone governance without a rebuild, though some workloads are worth migrating into fresh, vended subscriptions along the way.

The Delta export in Synapse Link is going. Here is where to move.

James Dettmer, Principal 5 November 2026 5 min read

Azure Synapse Link for Dataverse is not being switched off. Its Delta Lake export option is: closed to new customers since 15 October 2026, and gone for everyone in December 2027. We have already moved a production Dataverse estate from Synapse Link to Fabric Link. This is how we decide which way to go, and how to make the move without breaking what reads the data.

“Synapse Link is deprecated” is going round as a single sentence, and it is wrong in a way that matters. Read it as a whole-service retirement and you rush a migration you may not need. Dismiss it as noise and you find out in late 2027 that your reports have stopped refreshing. The accurate picture is four separate changes with four separate dates.

What is actually being retired

  • The Delta Lake (Parquet) export in Azure Synapse Link. Deprecated. Not available to new customers from 15 October 2026. Existing customers have to move to CSV output in Synapse Link, or to Link to Microsoft Fabric, by December 2027, when the option stops.
  • Export to Data Lake, the older finance and operations add-in installed through Lifecycle Services. Retired in November 2024 and stopping permanently on 30 November 2026, with no extensions. If anything still depends on it, that is the urgent one.
  • The Synapse Spark 3.4 runtime. The Delta export only works because a Spark pool in your own Synapse workspace converts the files. Spark 3.4 went out of support on 31 March 2026 and its jobs are being disabled in phases. A Delta link still running on a 3.4 pool is already on unsupported ground.
  • Not retiring: Azure Synapse Link itself. CSV export to your own storage account stays supported. Microsoft says it wants customers to be able to export data “well into the future”.

Two ways out, and they are not the same thing

Synapse Link with CSV output keeps the shape you have now: your storage account, your network rules, your managed identities, your pipelines. Choose it when the data has to land in a lake you control, or when what reads it is not Microsoft’s.

Link to Fabric is a different model. Dataverse keeps a Delta Parquet replica of the selected tables in its own managed storage, in the same region as the environment, and Fabric reads it through shortcuts in a lakehouse. Nothing is copied into a storage account of yours, there is no pipeline to run, and the data stays inside the Dataverse governance boundary. Choose it when the consumers are Power BI and Fabric.

If Delta was the reason you chose the Delta option in the first place, Fabric Link is now the only Microsoft route that gives you Delta directly from Dataverse without running a Spark pool of your own.

The cost moves rather than disappears

Fabric Link removes the storage account, the Spark pool hours spent converting files to Delta and, if nothing else uses it, the Synapse workspace. What it adds is Dataverse database storage. The replica counts against the environment’s database capacity, and it shows up in the Power Platform admin center as extra files named after each table with an “-Analytics” suffix. Database capacity is the dearest of Dataverse’s three storage types.

So check headroom before you link, not after. Only the tables you select consume storage, and the wizard selects every change-tracked table by default, so clear the ones nothing reports on. A handful of system tables are always included and cannot be removed.

What changes for whatever reads the data

Creating the link is a wizard. The work is downstream, and most of it sits in four places.

  • Serverless SQL. Fabric links using low-latency sync write Delta with deletion vectors, which Synapse serverless SQL pools cannot read in every scenario. Views and reports that query through serverless SQL need to move to the Fabric SQL analytics endpoint. Keeping them means adding a notebook that rewrites the tables without deletion vectors, with the delay and scheduling that brings.
  • Empty strings. Low-latency sync keeps an empty string as an empty string; Microsoft notes that earlier Fabric links converted them to NULL. Check any filter or measure that relies on NULL to mean blank, because a change here fails silently.
  • Choice metadata. Under low-latency sync the OptionsetMetadata and GlobalOptionsetMetadata tables have no createdonpartition column. Queries that name it need changing.
  • Coverage. Only tables with change tracking enabled can be linked. Anything you were getting some other way needs change tracking switched on, or a different route.

The sequence that keeps it boring

  1. List every consumer first. Each report, semantic model, pipeline, notebook and serverless SQL view that reads the Synapse Link output. That list, not the data volume, is the size of the job.
  2. Check Dataverse database capacity, and decide the table list before linking rather than accepting the default.
  3. Run both links side by side. Create the Fabric link while Synapse Link carries on, and reconcile row counts table by table before anything is repointed.
  4. Repoint consumers one at a time, starting with the ones that hurt least if they break.
  5. Know the unlink rule before you build on it. Unlinking deletes the lakehouse the link created, and it will not complete while any pipeline, copy job or semantic model still references it. Plan for that before reporting is layered on top.
  6. Retire last. Delete the Synapse Link profile, the Spark pool and the storage account only once nothing reads them.

Which way to go

  • Still on Export to Data Lake: move now. It stops on 30 November 2026.
  • On Synapse Link Delta, read by Power BI or Fabric: Fabric Link.
  • On Synapse Link Delta, read by tools outside Microsoft, or required in your own lake: Synapse Link with CSV output, and plan for the format change downstream.
  • On Synapse Link CSV: no deadline. Move when Fabric becomes your platform, not before.

December 2027 sounds like plenty of time. It is, until you count what reads the data. Creating the link is the short part; repointing a reporting estate that nobody has inventoried is not. We have made this move on a production estate and can run it again, and the consumer inventory is the place to start.

Questions this usually raises

Is Azure Synapse Link for Dataverse being retired?

No. The service stays, with CSV export to your own storage account. What is going is its Delta Lake (Parquet) export option: closed to new customers from 15 October 2026 and removed in December 2027.

Does Fabric Link cost more than Synapse Link?

It moves the cost rather than removing it. You stop paying for the storage account and the Spark pool that converts files to Delta, and start consuming Dataverse database capacity for the replica, plus Fabric capacity to use it. Which comes out cheaper depends on how many tables you link and how much database capacity you have spare, and the Power Platform admin center shows you the second before you commit.

Can we keep our Synapse serverless SQL views?

Not reliably on low-latency sync, because the Delta tables it writes use deletion vectors. Microsoft’s guidance is to move those queries to the Fabric SQL analytics endpoint, or to rewrite the tables with a notebook, which adds delay.

How long does a migration take?

Creating the link is the short part. The time goes on repointing whatever reads the old output, so the honest estimate comes from a list of consumers rather than from the size of the data. We can produce that list before you commit to anything.
